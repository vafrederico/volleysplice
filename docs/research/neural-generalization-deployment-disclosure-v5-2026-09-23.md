# Visible deployment limits in the report

V5 adds one always-visible note beside the precision-transfer explanation. The
sweep measures offline accuracy. DINO FP16 uses CUDA, while the mixed INT8
encoder's native-CPU results do not establish browser accuracy because its
earlier desktop Chrome parity check failed. No physical-phone latency, peak
memory or thermal qualification has been performed. Earlier graph-only checks
do not qualify every retrained checkpoint or the complete video pipeline.

The renderer delegates to the byte-pinned V4 source. Packed report content,
the exact source download, membership filters, comparison logic and numerical
values remain unchanged. Only the note and presentation-version/provenance
labels differ. A separate registration binds V4, the prior DINO precision and
browser qualification records, and the prior distilled-MobileNet graph check.

The V5 real QA source preserves every V4 assertion and adds visible-note checks
in every tested view. Its explicit source derivation changes only V5 renderer
identity/version/receipt labels and the added note assertions. Synthetic smoke
uses the existing V4 fixture and remains clearly synthetic; final publication
still requires actual audited data, complete transport/download parity, and
manual review of desktop and 390-pixel screenshots. All generated files and
browser temporary data remain on the NAS.

The registration names the prior precision protocol and DINO browser report
under `2026-09-23-recall-distillation/dino-precision-v1`, together with the
distilled graph report under `runtime-distilled-mobile-browser-v1`. Those
historical engineering checks support the qualification disclosure; their
accuracy results are not imported into or substituted for this study's rows.
