# Student inference with explicit numerical-audit cache provenance

V3 preserves the frozen v2 queue and all model, feature, fitting, inference, replay, selection and outcome functions. It retains the same 27 logical tasks, 20 physical encoders, 42 recordings, four checkpoints, owner-and-all-fit-descendant prerequisites, CPU2-3 affinity, nice10, and resource/concurrency floors. The separately registered numeric execution adapter shares verified file identities within one process. It replaces only registered digest bindings while calling the unchanged numerical auditor's `main` with its exact original argv. Every non-numeric command uses the original runner unchanged. This does not qualify mobile inference speed.

The root first requests v2's normal STOP file and waits for its actual successful exit after the active owner's raw inference, numerical replay and parent completion gates. Existing files and logs remain intact. Registration then verifies an exact all-27 inventory: completed uncached numerical audits and their prior v2 completion receipts, or tasks whose numerical audit and inference output directory are absent. Partial unreceipted inference output prevents registration and must be preserved for investigation. No prior unknown exit is converted into a successful exit.

The v3 plan pins that classification, the preserved v2 plan/source and actual stopped-worker identity/exit, the numerical execution plan and byte-exact cold/warm qualification. Each newly audited task requires `student-inference-cache-execution-fp32.json` beside its numeric gate. The companion binds the numerical result, original command, adapter and frozen auditor sources, task, panel, fit audit, touched files and signatures. A numerical gate with the old auditor hash alone is insufficient for these tasks. Preexisting uncached gates must remain byte-identical and must not acquire cache companions.

Only the frozen inference numerical-auditor command is intercepted. Model inference, student feature extraction, reuse and reuse auditing still use their unchanged subprocess commands. One adapter instance persists across logical tasks; numerical and replay functions are not replaced. The queue requires every companion before accepting a task and verifies all 27 tasks through the original completion gate. Root's independent cold closure and finalizer companion validation remain mandatory before publication.

The new root execution grant uses the v3 schema and pins the numeric execution plan, classification and v2 exit. An explicit schema view lets the unchanged v2 slot validator enforce its existing recovery-slot checks without modifying the saved grant. Runtime output, logs, cache, temporary files and qualification artifacts stay on the NAS. Accuracy outcomes still wait for the global 162-selection freeze.
