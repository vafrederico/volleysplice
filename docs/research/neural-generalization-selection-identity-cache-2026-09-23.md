# Explicit immutable file-identity cache for original-corpus calibration

The first original-corpus selection reread about 11.8 GB of historical provenance in 204 seconds. Its ordinary audit and independent companions repeated the same closure. The original duration-comparison audit and companion passed after reading about 24.2 GB, followed by a passing uncached correction gate. Running independent processes for all 18 original deployment selections would repeat this work hundreds of times. The randomized/proxy selection worker continues independently.

This amendment changes hashing orchestration only. A process-local cache explicitly substitutes three bindings: `neural_recall_sweep.identity`, its imported alias in `neural_recall_sweep_adapters`, and `neural_generalization_inputs.sha`. No decoder, metric, candidate, floor, fitting, audit-arithmetic or label function changes. The existing verified-reference cache is cleared between stages. Each substituted binding returns exactly the existing path and SHA representation.

The first request reads and hashes all bytes. Reuse requires identical device, inode, size, modification nanoseconds and change nanoseconds. Every cold read checks stat metadata before and after reading. A metadata change triggers a full diagnostic rehash and then fails, including an identical-byte rewrite. Every touched file is checked again at stage completion. Tests cover same-size content changes with restored modification times, metadata-only changes, read races, alias parity and restoration after errors. Cached values are never loaded from a prior process.

Before new original tasks run, the cached selector repeats the already-passed first original AV selection and must reproduce its saved JSON byte for byte. The original selection is preserved. Every executed selection, ordinary audit and correction audit gets an explicit sidecar naming the three substitutions, immutable source plan, input and output identities, touched-file identities and stat metadata. The first original task's three already-passed outputs are registered as preexisting; the remaining 51 stages retain their individual receipts. Restarting does not import prior cached hashes.

An independent final process reconstructs the complete 18-task, 54-stage inventory, including the qualification and all preexisting outputs. It independently cold-hashes the union of every stage's touched files and the explicitly declared numerical evidence inventories, then rechecks metadata before passing. A narrowed inventory, omitted stage, stale required reference, changed bytes or changed stat metadata fails. The receipt records stat signatures for its entire cold-read closure. Later evaluation/publication checks rehash the gate and source plan and require every closure stat signature to remain exactly identical; they do not reread the same 12 GB for every metric cell. The final independent numerical result audit remains unchanged and performs its own uncached verification.

The cold boundary includes all plan/code identities, stage inputs and outputs, selection evidence and score shards, ordinary-audit references and execution sidecars, correction-audit evidence, all 18 fit-numerical gates and their declared evidence, and the historical refit audit's declared references and checks. Known duration/serialization companion and delegated-base documents are expanded only through their named numerical-evidence fields. The auditor rejects missing required fields and unsupported gate schemas. Arbitrary referenced JSON is not recursively interpreted as a new dependency: the bound bytes of source documents preserve their informational history, including old moved paths, browser fixtures and raw-video identities that the unchanged selection auditors do not read. A preliminary metadata scan of generic recursion reached at least149.19GB and unavailable historical paths; the explicit numerical-evidence estimate is13.03GB across2,979files, with no missing files or raw videos. Actual touched-file inventories remain exhaustive and can only increase the final cold scope.

`scripts/generalization-selection-cache-execution.py` requires this cold gate before it delegates the unchanged global 162-selection freeze. A separate global cache-publication sidecar binds the exact frozen selection snapshot and cold gate. The same sidecar is required before external evaluation, the complete result audit and publication. The existing independent ordinary, correction, duration-comparison and endpoint-serialization gates remain mandatory. The numerical result/index/report payload is unchanged; the final audit additionally declares this hashing execution history. No additional-video outcome metric is opened before all 162 selections freeze.
