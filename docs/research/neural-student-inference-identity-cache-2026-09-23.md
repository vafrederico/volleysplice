# Student inference audit execution cache

This execution amendment preserves the original numerical auditor, image extraction, raw scores, labels, source splits, models, checkpoints, calibration choices and replay tolerances. The original auditor hashes image arrays through its independent Evidence helper and again through the inference input loader. The first completed student audit named 467 files totaling 15.87GB, including 15.338GB of shared images and teaching-image arrays. The existing streaming parent already retains its closure-verification dictionary; its initial closure duration must not be extrapolated across every owner.

The additive adapter retains one original `IdentityCache` instance in the current process. It starts empty; saved cache inventories are never imported. The original three disclosed hash bindings remain unchanged. A separate, explicitly registered helper-factory wrapper calls the original numeric helper factory, then binds only the freshly loaded student auditor's `digest` function to the same cache. Evidence methods and every numerical function retain their original objects. The original numeric `main` receives the exact command arguments, retains two Torch CPU threads, and writes the original audit payload. Argument, stream, helper and hash bindings are restored after each invocation, including failures. A failed cache process cannot continue.

The adapter accepts only the registered 27 student FP32 inference targets and two qualification copies. Each new numerical output requires `student-inference-cache-execution-fp32.json`. Its companion names the adapter and frozen auditor separately, records the exact arguments, named numerical evidence, touched-file hashes and full device/inode/size/mtime/ctime signatures, cold/hit byte counters, and memory snapshots. The original auditor identity identifies the unchanged numerical source; it is never sufficient alone to qualify a newly cached execution. A queue plan separately freezes the set of preexisting uncached outputs. Unexpected, partial or companion-less new outputs fail closed and remain preserved for inspection.

Qualification replays the first completed owner into two new NAS outputs, once with an empty cache and once with the same warm process-local cache. Both complete audit payloads must be byte-identical to the saved uncached audit. The warm pass must perform no new cold hash, and its touched-file inventory must equal the cold pass. This qualification computes independent tensor replay, never accuracy metrics or selections.

Each stage identifies its process with the Linux boot ID, PID and start-time ticks, plus a monotonic stage ordinal. The qualification stages must share that complete process identity and have ordinals one and two. This distinguishes a later process that reuses the same PID.

Before final publication, a separately implemented process must physically rehash the union of every touched file and each audit's named numerical evidence, together with the execution plans, sources, companions and delegated audit payloads. Full pre/post stat checks remain mandatory. No arbitrary referenced JSON traversal is required. The finalization workflow must bind this cold closure and every expected execution companion before and after the unchanged numerical result audit. Per-task companion validation checks disclosure and unchanged signatures; it does not pretend to replace that independent final physical rehash.

All outputs and temporary data stay on the NAS. The execution queue changes only at an observed quiescent owner boundary; current v2 workers and completed artifacts remain unchanged. Resource floors and maximum worker concurrency remain in force. Runtime differences include filesystem contention and Windows/WSL memory pressure and are not mobile or hardware benchmarks.
