# Android project side-switch evidence

Android feedback schema v3 imports retain `initialInference.sideSwitch` in the
native project and editor seed. The retained result includes the model identity,
feature and candidate contracts, every Float64 proposal row, and the selected
events with their original timestamps, probabilities, kinds and source-range IDs.
Bundle warnings also survive project persistence and re-export.

`source.generateSideSwitchMarkers` is a boolean independent of raw output
presence. An absent field uses the historical web default, true. Null, strings
and other nonboolean values are rejected. The Android exporter always writes the
flag, including false when a disabled project still retains raw output. Existing
native saved-project migrations retain their own historical defaults.

Missing or null raw output is unavailable evidence. A valid zero-row matrix with
no candidates is completed, healthy output. With serving-side output available,
score preparation remains ready for completed switch output, or when switch
generation is disabled; an enabled project missing switch output needs preparation.

Import and draft restoration preserve moved automatic markers, manual markers,
their provenance, and removed-model-marker tombstones. Reset creates a fresh draft
from retained inference: it clears manual changes and tombstones and restores the
original automatic timestamps when generation is enabled. Disabled generation
preserves saved corrections until reset and creates no automatic switches on reset.
Legacy corrections remain usable without raw evidence, but reset cannot reconstruct
automatic events that were never retained.

The parser checks the supported 34-column feature contract, candidate contract,
integer dimensions, the 25,000,000-value numeric limit, exact little-endian Float64
shape and canonical base64 byte length before allocating the matrix. It rejects
nonfinite features, invalid or duplicate events, nonnumeric or out-of-source
timestamps and probabilities, and malformed source-range ID arrays. Validation
finishes before import can publish a project, change selection, or hydrate caches.
Archived model IDs and fingerprints remain evidence with a supported data contract;
they do not qualify an enabled switch detector for a new current-model analysis.

The contract follows reviewed web implementation `fb060369488a0a5a7c04d13996046e756db3317b`.
The shared synthetic fixture `android/app/src/test/resources/side-switch-web-project.json`
was generated by that revision's production exporter and accepted by its production
validator. Its synthetic serve evidence uses the production component IDs and rally
agreements so it satisfies Android's existing serving-side validation as well.
No web implementation files are copied into this change.

`SideSwitchFeedbackTest` uses the production parser, exporter, stored-project and
editor-seed codecs, marker reducer and reset path. It writes both preference variants
to ignored build output for validation by the reviewed web parser.
`SideSwitchFeedbackInstrumentedTest` shares the same fixture and exercises actual
project/draft disk persistence, reopening, metadata relinking, reset, and rejection
before any cache or project publication. Metadata relinking does not qualify a
physical document provider, source fingerprint, MP4 export, or fresh inference run.

Integration with portable review preferences must retain these importer/exporter
changes independently of `corrections.ui`. Draft restoration must keep passing the
project's explicit detector preference to `ScoreReducer.seedModelMarkers`; reset
must continue to create a fresh draft from the retained seed. This change starts
from the approved Android cacheless-cleanup archive base and does not incorporate
the separate unreadable-draft or draft-save-error changes.
