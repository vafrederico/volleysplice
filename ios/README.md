# VolleySplice for iOS and iPadOS

Native Swift port of the Android app. `Sources/VolleyCore` contains portable DSP,
model inference, project formats, scoring and editor math. `App` contains SwiftUI,
AVFoundation, PhotoKit and thin Objective-C++ bridges for OpenCV primitives.
Android is the reference for analysis contracts and editor behavior.

## Build

The app targets iOS/iPadOS 17+ and uses Swift 5 language mode with Xcode 26.3.
The bundle identifier is `com.vafrederico.VolleySplice`. The checked-in Xcode
project is generated by `scripts/generate-project.py`; change the generator
when adding targets, resources or build settings.

On the configured Windows/macOS lab:

```powershell
./ios/scripts/prepare-opencv.ps1
./ios/scripts/test-core.ps1
./ios/scripts/build-device.ps1 -Unsigned
./ios/scripts/build-device.ps1 -Install
```

The helpers use the pinned `ios-build-host` SSH alias and configuration under
`E:/wslmac`. Follow the shared iOS Windows/macOS Lab skill for starting, signing,
device access and shutdown. Xcode can remain closed for command-line builds;
signing requires the configured account, unlocked keychain and valid provisioning
profile. The signing helper verifies the app identity, paired device and expiry,
then compares the downloaded IPA hash before installation.

`scripts/prepare-source.py` uploads an explicit source manifest to
`~/wslmac-projects/volleysplice`. It stages canonical models from
`android/app/src/main/assets` and test inputs into generated `Fixtures/` resources.
Do not commit that generated directory, recordings, signing files or build output.
Small synthetic test assets under `Tests/Fixtures` are intentional source inputs;
see their [provenance](Tests/Fixtures/README.md).

OpenCV 4.12.0's official static iOS framework is required at
`~/wslmac-dependencies/opencv-4.12.0/opencv2.framework`. The preparation helper
verifies its pinned download hash. Retain upstream Apache-2.0 license notices
when distributing. Swift owns feature reductions, DSP and model logic; OpenCV
provides color conversion, flow, filtering, phase correlation and morphology.

Builds, installs and physical tests run serially. The Mac lab has no GPU
acceleration: use the physical iPad for real recording analysis and video export.
Keep generated artifacts outside the repository. See [Testing](TESTING.md) for
commands, test coverage and hardware limitations.

## Recording access and storage

Files recordings are read in place using a local access bookmark. Camera Roll
selection uses PhotoKit's original AVURLAsset and persists only its local asset
identifier. The app reacquires access for reopening and queued work rather than
copying the movie into private storage. Photos may download an iCloud original;
edits made in Photos are not applied to that original recording.

If access is lost, re-link the original video through Files or Camera Roll.
Fingerprint and duration checks protect existing edits against a mismatched
recording. Unfinished queue items also offer Re-link video. New analyses use
the full video frame; saved projects retain their recorded analysis region.

Documents exposes Files sharing and contains local projects and small durable
draft journals. Feature checkpoints live in Library/Caches. Manage storage in
setup Settings and editor More accounts for projects, legacy recording copies,
exports, caches, temporary files and Recently deleted (`Documents/.Trash`).
Active files and unfinished queue inputs are protected. Cleanup never deletes
external Files or Camera Roll originals. Delete current project removes its
local project and journal while retaining source media and separate exports.

## Analysis and project formats

The pipeline samples visual frames at 4 Hz, builds 73 visual, four temporal and
27 audio columns, and computes percentile ranks and 520-column context. It runs
both production rally/serve/dead heads, ensemble merging and optional suppression.
Score preparation adds the frozen 237-column serving-side extractor and hybrid
serve gate, followed by the 34-column team-switch model. Specialist frames are
shared and completed features are checkpointed for retry.

The serial durable queue handles analysis, deferred scoring and video export
while another project remains editable. Inputs and export snapshots are fixed
when queued; finished scoring merges into current user edits. Removing active
work drains its worker before releasing the slot. Relaunch marks interrupted
work for explicit resume. On iOS 26+, analysis requests system-granted continued
processing; earlier versions and video exports require the foreground.

Local projects use `volleycut-ios-project`. Cross-platform exchange uses
`volleycut-model-feedback` schema v3 with features, original inference and user
corrections, without source media or device-local access credentials. See
[Project interoperability](PROJECT-INTEROPERABILITY.md) for known preservation
gaps; accepting a file does not establish lossless import and reexport.

## Editor layout

The iPad supports both landscape orientations only. iPhone portrait uses a
stacked editor; landscape uses three panes when its usable area is at least
640 by 300 logical points. The normal wide-window breakpoint is 840 by 360.
Orientation declarations live in `App/Info.plist`, including the iPad full-screen
compatibility setting.

UI size is shared by setup and editor: 60-125% in 5% steps. Default chooses 75%
on landscape iPhones and 100% otherwise. Explicit choices persist until Default
is selected. Scaling preserves Dynamic Type, applies once to app-owned sheets,
and leaves native pickers and menus at system sizing.

Phone landscape starts with a player fitted around the transport, timeline and
legend. Dragging selects a saved manual height up to 1,200 logical points;
long-press the resize handle and choose Fit video and timeline to restore fitting.
Phone player and sidebar preferences are separate from iPad/portrait preferences.
The right sidebar minimum includes reclaimed space opposite the notch without
overwriting its saved width on rotation. The header remains inside the safe area.

Phones use compact controls and a four-row marker viewport, with fixed icon
columns and no marker/awarded-count captions. iPad retains detailed headings.
The resize handle shares the phone landscape transport row with time, speed and
Play; source-time seeking remains available through the game timeline.
Display preferences do not change project features or exported video dimensions.

## Video export

Save final video asks for Camera Roll or Files before queueing. Files encodes
and stages directly in the coordinated selected folder. Camera Roll encodes a
closed private movie and imports using `shouldMoveFile = true`; successful import
removes it, while failed imports retain it for recovery. Delivery receipts guard
against duplicate imports after known success or an ambiguous crash.

Output is upright H.264/AAC MP4 with embedded chapters and a UTF-8 YouTube chapter
sidecar. Chapter authoring preserves encoded media and byte offsets, appending a
text track and replacement metadata; fast-start network playback optimization
is not retained. Source recordings are never modified.

The score compositor preserves source pixels outside overlays and supports
tagged SDR Rec.709/601 with right-angle rotation. Unsupported color formats
produce an explicit error; export can proceed with overlays disabled. HDR/wide
color overlays and Android's detailed codec/thermal benchmark controls are not
implemented. Full-match export and provider failure cases require hardware
validation described in [Testing](TESTING.md).
