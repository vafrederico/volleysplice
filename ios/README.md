# VolleySplice for iOS and iPadOS

Available for iPhone and iPad on [the App Store](https://apps.apple.com/us/app/volleysplice/id6812621538).

Native Swift port of the Android app. `Sources/VolleyCore` contains portable DSP,
model inference, project formats, scoring and editor math. `App` contains SwiftUI,
AVFoundation, PhotoKit and thin Objective-C++ bridges for OpenCV primitives and
ONNX Runtime.
Android is the reference for analysis contracts and editor behavior.

The default rally-review workflow and available Windows validation are documented
in [Courtside Deck](COURTSIDE-DECK.md). The existing full Editor remains available
through the Editor pill; all workspace tabs share the same draft and AVPlayer.

Restoring original model ranges keeps their saved rally IDs and existing score
corrections. Linked serve markers follow the restored boundaries and later edits;
removing a restored rally also removes its linked serve from visible scoring.

## Testing phone layouts on iPad

In a Debug build, open the Settings cogwheel and enable **Test as iPhone** under
Developer testing, then choose **iPhone model**:

| Model | Portrait size (points) |
| --- | --- |
| iPhone SE (3rd gen) | 375 × 667 |
| iPhone 13 / 14 (default) | 390 × 844 |
| iPhone 16 Pro | 402 × 874 |
| iPhone 16 Pro Max | 440 × 956 |

The app uses a centered viewport with approximate safe-area spacing and phone
layout rules. Rotate the iPad to swap width and height for landscape testing.
Disable the toggle to return to the normal
iPad workspace. Switching preserves the project, edits, selected pill and player.
The toggle and selected model are also available from setup Settings and persist
across launches. Changing models keeps the same project, edits, pill and player.

This runs the native controls and AVPlayer on the iPad. Modal presentation,
keyboards, alerts and file/share pickers still belong to iPadOS; it does not emulate iPhone hardware,
display density or device-specific safe areas. Release builds contain neither
the toggle nor the phone-viewport behavior.

For repeatable controls checks, a Debug build can be launched explicitly with
`--device-ui-fixture`. This opens the bundled synthetic 20-second test project;
normal launches never create it. Its reserved destination is replaced only if it
already identifies itself as a synthetic fixture. Existing projects, source
recordings and queue entries are preserved.

## Build

For a signed App Store/TestFlight release without a local Mac, use the manual
[GitHub Actions release workflow](RELEASING.md). That guide covers Windows
certificate creation, GitHub secrets, build artifacts, and optional uploads.

The app targets iOS/iPadOS 17+ and uses Swift 5 language mode with Xcode 26.3.
The bundle identifier is `com.volleysplice.VolleySplice`. The checked-in Xcode
project is generated by `scripts/generate-project.py`; change the generator
when adding targets, resources or build settings.

On the configured Windows/macOS lab:

```powershell
./ios/scripts/prepare-opencv.ps1
./ios/scripts/test-core.ps1
./ios/scripts/build-device.ps1 -Unsigned
./ios/scripts/build-device.ps1 -Install
```

The helpers use the pinned `${VOLLEYCUT_IOS_SSH_HOST}` SSH alias and configuration under
`${VOLLEYCUT_IOS_LAB_ROOT}`. Follow the shared iOS Windows/macOS Lab skill for starting, signing,
device access and shutdown. Xcode can remain closed for command-line builds;
signing requires the configured account, unlocked keychain and valid provisioning
profile. The signing helper verifies the app identity, paired device and expiry,
then compares the downloaded IPA hash before installation.

`scripts/prepare-source.py` uploads an explicit source manifest to
`${VOLLEYCUT_IOS_REMOTE_PROJECT_ROOT}`. It stages canonical legacy models from
`android/app/src/main/assets`, the selected public neural bundles verified against
`models/distilled-large/ios-manifest.json`, license notices and test inputs into
generated `Fixtures/` resources.
Do not commit that generated directory, recordings, signing files or build output.
Small synthetic test assets under `Tests/Fixtures` are intentional source inputs;
see their [provenance](Tests/Fixtures/README.md).

OpenCV 4.12.0's official static iOS framework is required at
`~/wslmac-dependencies/opencv-4.12.0/opencv2.framework`. The preparation helper
verifies its pinned download hash. Retain upstream Apache-2.0 license notices
when distributing. Swift owns feature reductions, DSP and model logic; OpenCV
provides color conversion, flow, filtering, phase correlation and morphology.

Builds, installs and physical tests run serially. The Mac lab has no GPU
acceleration: use the physical iPad for real recording analysis and video export.
Keep generated artifacts outside the repository. See [Testing](TESTING.md) for
commands, test coverage and hardware limitations.

## Recording access and storage

Files recordings are read in place using a local access bookmark. Camera Roll
selection uses PhotoKit's original AVURLAsset and persists only its local asset
identifier. The app reacquires access for reopening and queued work rather than
copying the movie into private storage. Photos may download an iCloud original;
edits made in Photos are not applied to that original recording.

If access is lost, re-link the original video through Files or Camera Roll.
Fingerprint and duration checks protect existing edits against a mismatched
recording. Unfinished queue items also offer Re-link video. New analyses use
the full video frame; saved projects retain their recorded analysis region.

Documents exposes Files sharing and contains local projects and small durable
draft journals. Feature checkpoints live in Library/Caches. Manage storage in
setup Settings and editor More accounts for projects, legacy recording copies,
exports, caches, temporary files and Recently deleted (`Documents/.Trash`).
Active files and unfinished queue inputs are protected. Cleanup never deletes
external Files or Camera Roll originals. Delete current project removes its
local project and journal while retaining source media and separate exports.

offers **Balanced Ã‚Â· BETA** and **Legacy model**. Only the selected bundle runs;
each neural variant has its own encoder, temporal model, scalers and decoder.
Saved projects and queued jobs keep their original selection. Older projects and
jobs without a selection retain Legacy. The editor's More menu returns to setup
to change the model; reanalysis saves a separate project and preserves prior edits.

All paths retain 4 Hz visual/audio features for project exchange and score
specialists. The two distilled MobileNetV3-Large + TCN bundles add 2 Hz image
embeddings and four temporal score heads. Legacy uses the two production
rally/serve/dead models, ensemble merging and optional suppression. Neural rallies
come from the selected temporal model; legacy evidence heads support serving-side
and team-switch decisions. Every neural rally is a serving-side candidate.
The shared specialist pass uses the frozen 237-column serving-side extractor and
34-column team-switch model. Balanced and Maximum coverage use their matching
encoder-paired serving heads: centered 13-frame windows plus 249 specialist/quality
features, with all three seeds required to accept the same side. Independent
serve-gate recovery reasons still require review. Legacy keeps its fixed-flight
serving classifier. Deferred scoring generates sparse matching encoder samples;
new analysis reuses its embeddings when they cover the complete serve windows.
Enabling score preparation also checks the saved serving-model fingerprint;
refreshing old output retains corrected markers and explicit deletions. Features and selected encoder embeddings are cached
for retry; preparation, video, audio, embeddings and rally inference have separate
progress measurements.

Neural inference uses pinned FP32 ONNX graphs with the CPU execution provider.
Hardware acceleration and physical-device speed/accuracy are not yet qualified.
The unaccelerated simulator supports functional checks and short video
probes, not an estimate of iPad GPU or Neural Engine performance. See
[Neural pipeline parity](NEURAL-PARITY.md) for the current contract and limits.

The serial durable queue handles analysis, deferred scoring and video export
while another project remains editable. Inputs and export snapshots are fixed
when queued; finished scoring merges into current user edits. Removing active
work drains its worker before releasing the slot. Relaunch marks interrupted
work for explicit resume. On iOS 26+, analysis requests system-granted continued
processing; earlier versions and video exports require the foreground.

Local projects use `volleycut-ios-project`. Cross-platform exchange uses
`volleycut-model-feedback` schema v3 with features, original inference and user
corrections. Neural projects include their selected model identity and four score
traces, but not embeddings, source media or device-local access credentials. See
[Project interoperability](PROJECT-INTEROPERABILITY.md) for known preservation
gaps; accepting a file does not establish lossless import and reexport.

## Editor layout

The iPad supports both landscape orientations only. iPhone portrait uses a
stacked editor; landscape uses three panes when its usable area is at least
640 by 300 logical points. The normal wide-window breakpoint is 840 by 360.
Orientation declarations live in `App/Info.plist`, including the iPad full-screen
compatibility setting.

UI size is shared by setup and editor: 60-125% in 5% steps. Default chooses 75%
on landscape iPhones and 100% otherwise. Explicit choices persist until Default
is selected. Scaling preserves Dynamic Type, applies once to app-owned sheets,
and leaves native pickers and menus at system sizing.

Phone landscape starts with a player fitted around the transport, timeline and
legend. Dragging selects a saved manual height up to 1,200 logical points;
long-press the resize handle and choose Fit video and timeline to restore fitting.
Phone player and sidebar preferences are separate from iPad/portrait preferences.
The right sidebar minimum includes reclaimed space opposite the notch without
overwriting its saved width on rotation. The header remains inside the safe area.

Phones use compact controls and a four-row marker viewport, with fixed icon
columns and no marker/awarded-count captions. iPad retains detailed headings.
The resize handle shares the phone landscape transport row with time, speed and
Play; source-time seeking remains available through the game timeline.
Display preferences do not change project features or exported video dimensions.

## Video export

Save final video asks for Camera Roll or Files before queueing. Files encodes
and stages directly in the coordinated selected folder. Camera Roll encodes a
closed private movie and imports using `shouldMoveFile = true`; successful import
removes it, while failed imports retain it for recovery. Delivery receipts guard
against duplicate imports after known success or an ambiguous crash.

Output is upright H.264/AAC MP4 for SDR or 10-bit HEVC/AAC MP4 for HDR, with
embedded chapters and a UTF-8 YouTube chapter sidecar. Chapter authoring preserves encoded media and byte offsets, appending a
text track and replacement metadata; fast-start network playback optimization
is not retained. Source recordings are never modified.

The CPU score compositor preserves decoded source samples outside overlay pixels
(and their shared 2x2 chroma blocks). It supports tagged SDR Rec.709/601, BT.2020,
and P3-D65, plus BT.2020 HLG and PQ HDR, with right-angle rotations and mirrored
orientations. Score graphics are converted from sRGB into the source gamut and
transfer; translucent edges and fades blend in linear light. HDR graphics use
203-nit diffuse white and the 1000-nit HLG reference display. NV12/P010 source
video is never converted through full-frame RGB.

Export verifies original primaries, transfer and matrix; HDR additionally requires
10-bit HEVC. Full-range sources are explicitly rejected because the current
preset path cannot promise range preservation. Untagged SDR can still export
without scores using AVFoundation defaults. Original Dolby Vision dynamic metadata
is not copied after pixels are edited; output retains the underlying HLG/PQ color
space, without promising the original Dolby Vision metadata. See
[HDR export validation](../docs/hdr-score-export.md) for platform coverage.

Full-match export, physical HDR display appearance and provider failure cases
require hardware validation described in [Testing](TESTING.md).
