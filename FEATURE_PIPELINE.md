# VolleySplice feature pipeline

This document is the rebuild contract for features consumed by VolleySplice models. It
defines the deployed production feature signature, how every production feature family
is computed, and which additional features are research-only. Model architecture,
targets, decoders, and ensemble behavior are documented separately in
[`MODEL_ARCHITECTURE.md`](MODEL_ARCHITECTURE.md). Trained artifacts and their source
videos are registered in [`MODELS.md`](MODELS.md).

## Status vocabulary

- **Production**: generated by both production clients and accepted by a checked-in
  production model artifact.
- **Production browser**: deployed and persisted by the production web client; Android
  parity and release qualification are tracked separately from port implementation.
- **Retained research**: implemented and reproducible, but not used by production.
- **Rejected research**: evaluated and explicitly not promoted. Keep it reproducible;
  do not silently reintroduce it.
- **Planned**: specified or proposed but not yet implemented and evaluated.
- **Historical**: required to load or reproduce an older artifact, not a candidate for
  new production inference without a new evaluation.

“Research” is used instead of “test” so experimental inputs are not confused with the
protected dataset test split.

## Normative sources and change control

The deployed contract is jointly pinned by the checked-in model artifact and feature
schema. The following precedence applies when rebuilding or diagnosing drift:

1. A production model's `featureVersion`, `featureConfig`, and ordered `featureNames`
   are the exact signature that inference must accept.
2. [`prod/src/lib/on-device/feature-schema.ts`](prod/src/lib/on-device/feature-schema.ts)
   is the canonical checked-in name/order and fixed-constant declaration.
3. [`analysis/features.py`](analysis/features.py) is the reference training extractor and
   mathematical reference for base-feature generation.
4. The production browser implementations are
   [`visual-features.ts`](prod/src/lib/on-device/visual-features.ts),
   [`visual-feature-reductions.ts`](prod/src/lib/on-device/visual-feature-reductions.ts),
   [`audio-features.ts`](prod/src/lib/on-device/audio-features.ts),
   [`pipeline.ts`](prod/src/lib/on-device/pipeline.ts), and
   [`feature-math.ts`](prod/src/lib/on-device/feature-math.ts).
   The production score-specialist implementations are
   [`serving-side-model.ts`](prod/src/lib/on-device/serving-side-model.ts),
   [`serving-side.ts`](prod/src/lib/on-device/serving-side.ts),
   [`side-switch-model.ts`](prod/src/lib/on-device/side-switch-model.ts), and
   [`side-switch.ts`](prod/src/lib/on-device/side-switch.ts). Their timestamp schedules
   are unioned by [`score-specialists.ts`](prod/src/lib/on-device/score-specialists.ts)
   and sampled by
   [`specialist-frame-sampling.ts`](prod/src/lib/on-device/specialist-frame-sampling.ts).
5. The Android equivalents begin at
   [`FeatureSchema.java`](android/app/src/main/java/com/volleycut/nativeanalysis/FeatureSchema.java),
   [`NativeVideoDecoder.java`](android/app/src/main/java/com/volleycut/nativeanalysis/NativeVideoDecoder.java),
   [`AudioFeatureExtractor.java`](android/app/src/main/java/com/volleycut/nativeanalysis/AudioFeatureExtractor.java),
   and [`FeatureMath.java`](android/app/src/main/java/com/volleycut/nativeanalysis/FeatureMath.java).

Do not fix a mismatch by changing only a name list or by reordering a model artifact.
A production feature change requires a new immutable feature version, new caches, a
retrained model, updated browser and Android implementations, and cross-platform golden
tests. Changing a formula, threshold, window, color conversion, resampler, pooling rule,
normalization exception, missing-value rule, or boundary rule is a feature-version
change even when the column names do not change.

## Production profile

The current production profile is `audiovisual-noise-normalized-audio-v3` with audio
profile `noise-normalized-bands-v3`:

```text
normalized source-time game window and normalized court ROI
                         |
             sample video at 4 Hz
             crop ROI, resize to 192x108
                         |
        73 visual + 4 temporal + 27 audio
                         |
                  104 base columns
                         |
     tied percentile rank within the game window
       except six absolute quality/availability columns
                         |
       nearest samples at -2, -1, 0, +1, +2 seconds
                         |
                  520 model inputs
```

The production constants are:

| Setting | Value |
| --- | --- |
| Analysis rate | 4 Hz; nominal step 0.25 seconds |
| Analysis image | 192×108 pixels |
| Spatial grid | 3×3, row-major from top-left to bottom-right |
| Audio | first decodable track, mono, 16,000 Hz |
| Audio DSP frame | 800 samples = 50 ms; non-overlapping |
| FFT | 1,024 samples with an 800-sample Hann window and zero padding |
| Context offsets | `[-2, -1, 0, +1, +2]` seconds, in that block order |
| Base dtype | finite `float32` values; timestamps are `float64` seconds |
| Production columns | 104 base; 520 contextual |

The configured game window, rather than an unrelated full source file, is the sequence
universe for percentile normalization and context clamping. The ROI is a normalized
`(x, y, width, height)` rectangle in source display coordinates. The cropped image is
resized with OpenCV `INTER_AREA`. Browser and Android decoders must preserve source-time
timestamps and display orientation before feature generation.

## Notation and shared reductions

For one 192×108 analysis image:

- `Y` is 8-bit grayscale luma and `S` is the 8-bit HSV saturation channel.
- `N` is the number of pixels and `D = hypot(192, 108)`.
- `mean`, population standard deviation, and linearly interpolated quantiles operate on
  all finite values in the named image or vector.
- A 3×3 grid uses rounded boundaries
  `round(k * size / 3)`; suffixes 0–8 are row-major.
- `flow=(u,v)` is dense Farnebäck flow from the preceding sampled analysis frame to the
  current one, using `(pyr_scale, levels, winsize, iterations, poly_n, poly_sigma,
  flags) = (0.5, 2, 13, 2, 5, 1.1, 0)`.
- The first sampled frame has zero frame difference, camera shift, and optical flow.

The browser uses RGBA→gray and RGBA→RGB→HSV; the Python training reference uses
BGR→gray and BGR→HSV. They are intended to produce the same channel meanings after
decode. Exact floating-point identity across OpenCV builds and media decoders is not
assumed; the checked-in tolerance and golden tests are the compatibility authority.

## Production visual features: 73 columns

### Appearance: 15 columns

| Output name | Definition before sequence normalization |
| --- | --- |
| `luma_mean` | `mean(Y) / 255` |
| `luma_std` | population `std(Y) / 255` |
| `saturation_mean` | `mean(S) / 255` |
| `saturation_std` | population `std(S) / 255` |
| `edge_density` | fraction of nonzero pixels after Canny thresholds 60/140 |
| `sharpness` | `min(var(Laplacian(Y)) / 2000, 5)` using a `CV_32F` Laplacian |
| `luma_grid_0` … `luma_grid_8` | per-cell `mean(Y) / 255` |

### Frame difference: 13 columns

Let `A = abs(Y - previous_Y)` in 8-bit luma units. `A` is all zero on the first
sampled frame.

| Output name | Definition before sequence normalization |
| --- | --- |
| `diff_mean` | `mean(A) / 255` |
| `diff_std` | population `std(A) / 255` |
| `diff_p90` | linearly interpolated 90th percentile of `A`, divided by 255 |
| `diff_active_fraction` | fraction of pixels where `A >= 18` |
| `diff_grid_0` … `diff_grid_8` | per-cell `mean(A) / 255` |

### Camera and image quality: 11 columns

Let `L = var(Laplacian(Y))`, `dark = fraction(Y <= 12)`, and
`bright = fraction(Y >= 243)`. Sobel gradients use kernel size 3. A pixel is low
texture when `hypot(SobelX, SobelY) < 8`. A grid cell is occluded when its mean is
at most 16 or at least 239 and its population standard deviation is at most 8.

| Output name | Definition before sequence normalization |
| --- | --- |
| `focus_quality` | `L / (L + 100)` |
| `blur_probability` | `1 - focus_quality` |
| `dark_fraction` | `dark` |
| `bright_fraction` | `bright` |
| `low_texture_fraction` | fraction of low-texture pixels |
| `occlusion_fraction` | number of occluded 3×3 cells divided by 9 |
| `visibility_quality` | `sqrt(focus_quality * exposure_quality * contrast_quality) * (1 - occlusion_fraction)`, with `exposure_quality=max(0,1-min(1,dark+bright))` and `contrast_quality=min(1,luma_std/0.12)` |
| `camera_shift_x` | phase-correlation horizontal shift divided by 192 |
| `camera_shift_y` | phase-correlation vertical shift divided by 108 |
| `camera_shift_magnitude` | `hypot(shift_x, shift_y) / D` before the component normalization above |
| `camera_shift_response` | phase-correlation response clipped to `[0,1]` |

Phase-correlation failure produces zeros for both shifts and response; it does not abort
analysis.

### Raw optical flow: 14 columns

Let `M = hypot(u,v)`.

| Output name | Definition before sequence normalization |
| --- | --- |
| `flow_mean` | `mean(M) / D` |
| `flow_p90` | 90th percentile of `M`, divided by `D` |
| `flow_active_fraction` | fraction of pixels where `M >= 1` pixel |
| `flow_median_x` | median `u / 192` |
| `flow_median_y` | median `v / 108` |
| `flow_grid_0` … `flow_grid_8` | per-cell `mean(M) / D` |

### Camera-compensated player-motion proxies: 20 columns

These are low-level residual-motion proxies, not detected or tracked players. Let
`u_med` and `v_med` be the component medians above, residual flow
`R=(u-u_med,v-v_med)`, and residual magnitude `RM=hypot(R)`. A residual pixel is
active when `RM >= 1` pixel.

For spatial entropy, compute the nine unnormalized cell means `g_i` of `RM`, then
`p_i=g_i/sum(g)`, and `-sum(p_i log(p_i))/log(9)`; return zero when the grid sum is
at most `1e-9`. For centroid and spread, use only pixels with `RM >= 0.5`, weighted
by `RM`, and normalized pixel-center coordinates `(x+0.5)/width` and
`(y+0.5)/height`. With no qualifying weight, centroid is `(0.5,0.5)` and spread is
zero.

| Output name | Definition before sequence normalization |
| --- | --- |
| `player_motion_mean` | `mean(RM) / D` |
| `player_motion_p90` | 90th percentile of `RM`, divided by `D` |
| `player_motion_active_fraction` | fraction of active residual pixels |
| `player_motion_active_zone_fraction` | fraction of 3×3 cell means at least 0.75 pixel |
| `player_motion_spatial_entropy` | normalized entropy of the nine residual cell means |
| `player_motion_centroid_x`, `player_motion_centroid_y` | weighted normalized centroid |
| `player_motion_spread_x`, `player_motion_spread_y` | square root of weighted normalized coordinate variance |
| `player_motion_coherence` | magnitude of the mean active residual vector divided by mean active residual magnitude, with denominator floor `1e-6`; zero when none are active |
| `quality_gated_player_motion` | `player_motion_mean * visibility_quality * camera_gate`, where `camera_gate=max(0,1-min(1,camera_shift_magnitude/0.03))` |
| `player_motion_grid_0` … `player_motion_grid_8` | per-cell `mean(RM) / D` |

## Production temporal visual features: 4 columns

At 4 Hz, a past one-second rolling mean includes the current sample and up to the
three preceding samples. A future half-second mean includes the current and following
sample. Windows shrink at sequence boundaries rather than padding with zeros.

Let `PM` be `player_motion_mean`, `AZ` be
`player_motion_active_zone_fraction`, `past1(x)` be the trailing four-sample mean,
`future0.5(x)` be the forward two-sample mean, and `future1(x)` be the forward
four-sample mean.

| Output name | Definition before sequence normalization |
| --- | --- |
| `player_motion_onset` | `max(future0.5(PM) - past1(PM), 0)` |
| `player_motion_collapse` | `max(past1(PM) - future0.5(PM), 0)` |
| `synchronized_stand_down` | `player_motion_collapse * max(past1(AZ) - future0.5(AZ), 0)` |
| `receiving_formation_change_proxy` | Euclidean norm of `future1 - past1` for motion centroid x/y and spread x/y, multiplied by `min(1,(past1(PM)+future0.5(PM))/0.015)` |

Despite its historical name, `receiving_formation_change_proxy` has no serving-side or
team identity input.

## Production audio features: 27 columns

Audio is placed on the source-time timeline before resampling. Decoder priming before
zero is trimmed, discontinuity gaps are represented by silence, and overlapping decoded
chunks are trimmed. The default browser path linearly resamples and quantizes to signed
16-bit-equivalent PCM to reduce drift from the FFmpeg training reference; the optional
libswresample WASM path has its own cache/runtime identity.

Each 50 ms DSP frame supplies RMS, absolute peak, a normalized magnitude spectrum, and
power in `[80,250)`, `[250,500)`, `[500,1000)`, `[1000,2000)`, `[2000,4000)`, and
`[4000,7800)` Hz. The last partial audio frame is zero-padded.

Let `rank(x)` be the tied percentile rank across all 50 ms frames in the analysis
window, and let `floor10(x)` be the causal trailing ten-second 20th percentile including
the current frame and using a shorter prefix at the beginning.

| Output name | DSP-frame definition before 4 Hz pooling |
| --- | --- |
| `audio_available` | 1 when a usable audio track produced samples; otherwise 0 |
| `audio_rms` | square root of mean squared PCM amplitude |
| `audio_peak` | maximum absolute PCM amplitude |
| `audio_peak_to_rms` | `clip(peak/(rms+1e-5), 0, 30)` |
| `audio_noise_floor` | `floor10(rms)` |
| `audio_snr` | `log1p(max(rms-noise_floor,0)/(noise_floor+1e-4))` |
| `audio_spectral_flux` | L2 norm of positive change from the previous normalized magnitude spectrum; zero for the first DSP frame |
| `audio_rms_novelty` | `max(rms-previous_rms,0)`; zero for the first frame |
| `audio_onset_strength` | `0.45*rank(spectral_flux) + 0.35*rank(rms_novelty) + 0.20*rank(peak)` |
| `audio_contact_like_transient` | `onset_strength * sqrt(rank(peak))` |
| `audio_onset_cadence` | trailing two-second mean of `audio_contact_like_transient` |
| `audio_cadence_collapse` | `max(trailing_2s_cadence - forward_1s_mean(contact_like), 0)` |
| `audio_seconds_since_transient` | seconds since a frame where contact-like is at least `max(0.72,p85(contact_like))` and peak rank is at least 0.60; initialized and capped at 10 seconds |

For each frequency band, let `P_b` be summed squared FFT magnitude,
`F_b=floor10(P_b)`, `E_b=max(P_b-F_b,0)`, and
`S_b=log1p(E_b/(F_b+1e-8))`.

| Output name | DSP-frame definition before 4 Hz pooling |
| --- | --- |
| `audio_noise_removed_broadband` | `log1p(sum_b(E_b)/(sum_b(F_b)+1e-8))` |
| `audio_noise_normalized_flux` | L2 norm across bands of `max(S_b-previous_S_b,0)` |
| `audio_band_<band>_snr` | `S_b` for each of the six bands |
| `audio_band_<band>_snr_flux` | positive one-frame change in `S_b`, zero on the first DSP frame |

### Pooling audio to video timestamps

For video time `t`, select DSP-frame centers in the closed interval
`[t-0.125, t+0.125]`. If none exist, use the nearest DSP frame. Use the arithmetic
mean for:

- `audio_rms`
- `audio_noise_floor`
- `audio_snr`
- `audio_onset_cadence`
- `audio_cadence_collapse`
- `audio_seconds_since_transient`

Use the maximum for every other non-availability audio feature. Set
`audio_available=1` directly. When audio is absent or undecodable, all 27 audio columns,
including availability, are zero.

## Sequence normalization and temporal context

For every non-absolute base column independently, sort all `N` values in the analysis
window and assign tied midranks:

```text
rank = (first_equal_index + (equal_count - 1) / 2) / (N - 1)
```

For a one-row sequence, every ranked value is 0.5. The following six columns bypass
sequence ranking and retain the extractor value:

- `audio_available`
- `focus_quality`
- `blur_probability`
- `occlusion_fraction`
- `visibility_quality`
- `camera_shift_response`

After normalization, each row gathers the nearest source row at `t-2`, `t-1`, `t`,
`t+1`, and `t+2` seconds. Equal-distance ties choose the earlier row; requests before
the first or after the last timestamp clamp to the nearest boundary row. Column names
are emitted in offset-major order, for example `t-2s/luma_mean` through
`t+2s/audio_band_4000_7800_snr_flux`.

Therefore references to 90/450 in the analysis package are not the current deployed

Feature caches must include source-content identity, ROI, analysis window where
applicable, extractor version/configuration, ordered feature signature, decode strategy,
and runtime/resampler variant. A cache generated with a different identity must be a
miss, never a partial reuse. The browser implementation is in
[`feature-cache.ts`](prod/src/lib/on-device/feature-cache.ts); Android uses
[`NativeFeatureCache.java`](android/app/src/main/java/com/volleycut/nativeanalysis/NativeFeatureCache.java).

The Android source now resolves YUV color range and matrix from each decoded output
buffer, falling back per field to the extractor's track metadata and, only when
unspecified, explicit BT.601/limited assumptions. This corrects the native decoder's
previous fixed limited-range conversion for full-range recordings. The shared
[`YuvColorConversion`](android/video-common/src/main/java/com/volleycut/video/YuvColorConversion.java)
is included unconditionally in the normal app and used by synchronous/asynchronous
AV extraction and both score specialists. Its runtime cache revisions are
`opencv-v2-decoded-yuv-color` and
`shared-gap5-mediacodec-decoded-yuv-color-gray-bgr-v3`; prior caches are incompatible.
This is a versioned native runtime correction toward the existing decoded-pixel
contract, not a new trained feature family. Weights, feature column signature, and
frame-sampling policy are unchanged. New Android analyses now use the full frame,
matching the web default; filename-based automatic crops are disabled. New project
identities and reuse checks include ROI geometry, so a saved cropped analysis cannot
satisfy or overwrite a new full-frame analysis. Existing saved/imported ROIs and edits
are preserved. Editor recovery records now retain the original ROI; older recovery
records with unknown geometry remain editable but cannot satisfy a new analysis
request. Corrected full-video runs are complete for production, Small, and Large;
an ordinary-editor pilot also completed both score specialists, playback, and
project recovery with full-frame ROI. Production predictions change despite unchanged
weights: this recording's export F1 improves but retained recall falls and one saved
human rally becomes wholly missed. Cross-platform feature accuracy still requires
qualification. See the
[native follow-up](docs/research/mobile-tcn-follow-up.md).

Both selected DINO-distilled Large choices also completed native FP32 CPU runs
using this corrected full-frame pipeline. Distillation preserves the four-region
960-channel encoder computation; neither DINO nor its training projector runs on
the phone. On the full benchmark source, each run saves 32,609,280 bytes of image
tokens, 67,104,960 bytes of fused 3,952-column inputs and 67,920 bytes of four-head
probabilities. These diagnostic files duplicate information and do not measure
minimum cache size or peak memory. Saved-input temporal and decoder parity passes,
but native extraction still loses recall relative to desktop. Fixed-checkpoint
counterfactuals recover most of the highest-F1 choice's loss by replacing native
audio/AV104 with desktop values; replacing embeddings alone does not. Native linear
audio resampling differs from desktop FFmpeg, but controlled same-PCM tests show
that it is secondary here. The [audio root-cause investigation](docs/research/android-audio-timeline-root-cause.md)
identifies a shared batched-decoder timing bug: the first packet's timestamp gap
is mistaken for its permanent decoded sample count. On the benchmark recording,
the resulting overlaps discard about 78.66s of PCM and audio features freeze
around 16m22.5s. Correcting feature timestamps alone cannot recover discarded
samples. The shared decoder now uses validated AAC-LC configuration with synchronous
fallback and PCM accounting checks. Audio/context cache identity and new-analysis
project provenance invalidate the affected inputs without removing reviewed projects.
Android and both web implementations also correct integer startup noise quantiles;
the web path does not have the packet-spacing defect. See the
[repair and validation report](docs/research/android-web-audio-fix.md) for device
evidence and remaining qualification limits.
The [distilled Large native benchmark](docs/research/distilled-mobile-large-native-benchmark.md)
binds timing, tensor identities and accuracy evidence through ledger
`private-reference-0223`.

## Production-browser serving-side pipeline

The production web client runs `serving-side-fixed-flight-v3` followed by
`serving-side-hybrid-serve-gate-v2`. The runtime is the checked-in
`prod/public/runtime/serving-side-85bc3325fbd4.json` asset (file SHA-256
`14f18bf0b0f326ccd7ef4b3d614a96a53dd9675df61813fd375677489d0e5a7c`). Android
deployment and cross-platform parity remain pending. These columns are a separate
candidate-conditioned matrix and never extend the deployed F104/520 rally schema.

The pipeline is candidate-conditioned. It runs at a saved rally/serve anchor and has
two independent parts:

1. a 237-input visual model always estimates physical camera-space serving side as
   `near` or `far`; and
2. a deterministic hybrid gate decides whether that side should be exposed as a serve,
   marked for review, or hidden as `not-serve`.

The gate is composition policy, not an input to or refit of the side model.

### Browser implementation and Android delta

The existing production F104/520 matrix cannot be passed to the serving-side model.
The browser generates a separate `SERVSIDE237-FLIGHT` matrix over the complete set of
candidate anchors in the recording. Native extraction, inference, hybrid gating, and
cache implementations now exist and execute in the complete-pipeline benchmark. This
does not establish physical-device feature/pixel/PTS parity or release qualification.
The following table retains the browser source and the Android equivalence requirements:

| Capability | Browser status | Android requirement |
| --- | --- | --- |
| Video decode, source timestamps, and ROI cropping | Requested timestamps are routed through one full sequential `VideoSampleSink` pass shared with the optional side-switch branch. Requested serving frames use the display-oriented ROI crop, 192×108 `fit: fill`, grayscale conversion, and exact clamped offsets. | Select the same frames at the same source timestamps and preserve display orientation before the ROI crop. Decoder strategy is an execution detail; converted pixels and feature rows must remain equivalent. |
| Court-flow values | Implemented as 82 values | Port the fixed top/bottom 32% ROI-relative service bands, median-translation-compensated Farnebäck flow, 3×3 opening, connected components, phase summaries, and deltas exactly. |
| Concentrated-flight values | Implemented as 155 values | Port the affine-compensated flight flow, p90 residual-energy isolation, 4×6 summaries, components, and transitions exactly. |
| Recording normalization | Implemented as column-wise stable tied midranks over all candidates; singleton rank is 0.5 | Do not reuse F104 normalization. Match stable tie behavior and reject non-finite raw values. |
| Side classifier | Runtime parser validates all names, vectors, geometry, thresholds, and policy | Package byte-equivalent parameters or a proven equivalent representation and match scores/verdicts within the declared tolerance. |
| Serve-head score series | Reused from both production bundles | Retain both aligned probability arrays and decoded contacts. |
| Ensemble rally intervals and agreement | Reused from the production union | Preserve exact merged starts, IDs, bounds, and agreement values. |
| Hybrid gate and review reason | Implemented with `serve-head`, `production-rally-recovery`, and `none` sources | Port exact inclusive window/threshold and recovery/review behavior. |
| Cache/parity coverage | Browser cache identity and focused runtime tests are implemented | Add durable Android cache identity plus raw-feature, rank, score, verdict, and gate parity fixtures before release. |

In short, production adds **237 new visual feature columns and one side-model score**.
It reuses the existing two serve-head score streams and ensemble rally agreement; those
reused values are gate evidence and must not be appended to the 237 model inputs. Human
near/far labels, visibility labels, contact-quality labels, and review answers are never
inference features.

### Court-flow bank: 82 inputs

`serving-side-court-flow-v2` samples eight ROI-cropped frames at offsets
`[-1.25, -0.75, -0.35, -0.10, 0.10, 0.30, 0.55, 0.85]` seconds from the anchor.
Farnebäck optical flow is computed for declared pairs, the median full-frame flow is
subtracted as translation compensation, and residual motion of at least one pixel is
morphologically opened before being summarized. The frozen browser runtime always uses
the bottom 32% of the ROI as `near` and the top 32% as `far`. The Python research
extractor can accept annotated service-zone anchors, but the fitted production corpus
used the ROI-relative fallback. Adding calibrated masks to a production client would
therefore require a new feature version, fit, and parity evaluation.

The ordered bank expands as follows:

- phases `pre`, `contact`, and `post`, each with nine statistics for both `near` and
  `far`: `flowMean`, `flowP90`, `activeFraction`, `largestComponentFraction`,
  `componentCountDensity`, `centroidX`, `centroidY`, `flowX`, and `flowY`;
- five per-phase `nearMinusFar` differences: `flowMean`, `flowP90`,
  `activeFraction`, `largestComponentFraction`, and `componentCountDensity`;
- for each zone, `contactMinusPre` changes in flow mean, active fraction, and largest-
  component fraction, plus `postMinusContact` changes in flow mean and active
  fraction; and
- three contact-change near-minus-far interactions for flow mean, active fraction,
  and largest-component fraction.

That gives `3 × (2 × 9 + 5) + 2 × 5 + 3 = 82` values.

### Fixed-flight bank: 155 inputs

`serving-side-concentrated-flight-grid-v1` samples nine ROI-cropped 192×108 frames at
`[-0.15, 0.05, 0.20, 0.35, 0.55, 0.80, 1.10, 1.40, 1.75]` seconds from the anchor.
It computes eight Farnebäck flow fields and robustly fits an affine camera-flow field
over normalized image coordinates. One trimmed refit retains the 75% smallest
residuals, allowing translation, rotation, and zoom to be removed. Residual flow is
normalized by frame dimensions; residual magnitude is normalized by the frame
diagonal. Motion energy is `max(magnitude - max(0.00075, p90(magnitude)), 0)`.

The eight frame pairs are averaged into `launch` (pairs 0–2), `early` (3–5), and
`late` (6–7). For each phase, the 4×6 grid emits:

- 24 normalized cell-energy fractions;
- four energy-weighted vertical-flow values, one per grid row; and
- 15 global values: `energyMean`, `activeFraction`, `centroidX`, `centroidY`,
  `spreadX`, `spreadY`, normalized `entropy`, `largestComponentFraction`, `flowX`,
  `flowY`, `divergence`, `bottomMinusTop`, `smallComponentEnergyFraction`,
  `smallComponentCentroidY`, and `smallComponentFlowY`.

Each of `launchToEarly` and `earlyToLate` then emits changes in nine of those global
values—vertical centroid/spread, entropy, vertical flow, divergence, bottom-minus-top,
and the three small-component values—plus four row-energy changes. The count is
`3 × (24 + 4 + 15) + 2 × (9 + 4) = 155`.

This concentrated residual-motion representation is an interpretable flight proxy,
not a claim that a ball or server was directly detected. Small connected components
mean at most four pixels or 0.25% of the frame, whichever is larger.

### Ranking, concatenation, and target

All 82 court-flow and 155 fixed-flight values are converted independently to tied
percentile ranks within their recording. A singleton rank is 0.5. The two banks are
concatenated in that order to form `SERVSIDE237-FLIGHT`. The class-balanced logistic
model uses median imputation, per-column mean/standard-deviation scaling, L2 `0.1`,
and a learned near-side threshold of `0.4783744762021848`; lower scores are `far`.
No audio or human visibility/contact annotation is an input to this side classifier.

The exact generated order is defined by
[`analysis/serving_side_v2.py`](analysis/serving_side_v2.py) and
[`analysis/serving_side_flight.py`](analysis/serving_side_flight.py). The authoritative
237-name order, fitted imputation/scaling vectors, weights, bias, and threshold are in
the versioned development evaluation artifact registered in [`MODELS.md`](MODELS.md).

### Hybrid serve gate

At the same source-aligned anchor, both deployed production serve heads are inspected
within ±1 second. If either head reaches its unchanged decoded threshold of `0.85`,
the side is exposed with decision source `serve-head`. If both miss, the anchor is
tested against the exact overlap-union production rally intervals. Containment inside
a `both-models` interval exposes the side with decision source
`production-rally-recovery` and mandatory review. All other candidates are
`not-serve`. Side-score uncertainty independently requests review at near probability
`[0.3121748736511044, 0.5028396703865513)`.

Production-rally agreement and serve-head scores are gate evidence, not additional
members of the 237-input side feature vector. The gate does not create, delete, or
move production rally intervals.

### Native neural input qualification

The complete-pipeline prototype has reproduced native and desktop temporal inference
and boundary decoding from their respective saved fused tensors, but this is not
video-to-feature parity. On `recording-044`, the benchmark used a cropped default ROI
while the frozen research manifest used full frame. Native visual conversion also
assumed limited-range BT.601 for a source declaring full-range BT.709, used point
sampling instead of the AV reference's area resize, and selected first-after rather
than nearest embedding frames. The quality and PTS scalar differences can hit the
training scaler's clipping limits.

Frozen-model feature substitutions recover Small's missing rally by replacing AV104
and quality scalars while retaining native embeddings. Large exhibits the same type
of feature-contract failure; this is not evidence that a different checkpoint or
calibration target was used. The diagnostic is registered at `private-reference-0217`
and described in [the input-drift report](docs/research/native-small-tcn-input-drift.md).
The corrected full-frame Small and Large device runs are registered at
`private-reference-0218`. Both completed all feature generation and score specialists.
Replaying the saved corrected tensors agrees with phone temporal probabilities within
8e-7 and reproduces the decoded boundaries. This verifies inference from those inputs,
not equality of native and desktop extraction. Both models recover the formerly wholly
missed rallies, but one end remains early and Large still splits one saved human rally.
Frozen feature substitutions identify residual AV104 differences as the cause of these
boundary discrepancies; replacing embeddings alone does not resolve them. Native audio
features are unchanged by the color/ROI correction. Do not treat these single-recording
results as cross-platform parity or a newly selected model. Keep runtime qualification
separate from the shipped feature contract until its acceptance gates are satisfied.

Existing DINO artifacts remain reproducible research, but further DINO work was
stopped at the user's request after the full native timing result. This changes no
feature signature or historical result.

The broader unimplemented backlog, including tracklets, stereo cues, calibrated court
geometry, and richer ball interactions, is in

### Side-switch v2 marker profile

`SIDE34-V2` is separate from the production 104/520 rally matrix. Each inter-rally
candidate samples four frames on each side of its midpoint within an 8-second flank and
a 0.75-second edge margin. OpenCV HOG proposals run at at most 1,280 pixels wide and
are restricted to normalized central-court bounds. Unlabeled weighted two-means over
the complete recording's candidate-frame foot positions sets the near/far divider;
event-local fits shrink toward that recording value so zoom and moderate reframing do
not rely on a fixed pixel boundary. Sparse local geometry falls back to the recording
calibration and is exposed through coverage features.

The 17 scalar base columns are:

- `paletteDistanceMean`, `paletteDistanceMinimum`,
  `paletteDistanceDisagreement`, `playerMinusBackgroundEvidence`,
  `geometryStability`, `paletteByGeometryStability`, and
  `areaPaletteByGeometryStability`;
- `sideSameAssignmentCostMedian`, `sideSwappedAssignmentCostMedian`,
  `sideSwapMarginMedian`, `sideSwapMarginLowerQuartile`,
  `sideSwapSupportFraction`, `sideSwapMarginVariance`,
  `sideUsablePairCount`, `sideMinimumCoverage`,
  `colorMomentFlipEvidenceMedian`, and `swapMarginByGeometryStability`.

Each scalar is paired with a missingness indicator, yielding 34 ordered classifier
inputs. The feature artifact also carries per-recording median/MAD variants and an
unlabeled color-moment orientation coordinate, but grouped development selection chose
the raw combined family. Gap duration is audit context only and is excluded from every
v2 learned feature set. The exact implementation is
[`side_switch_v2.py`](analysis/side_switch_v2.py); extraction is
[`extract-side-switch-v2.py`](scripts/extract-side-switch-v2.py).

### Side-switch v3 low-resolution profile

inputs are same/swapped assignment costs, swap margin, orientation-flip evidence,

### Side-switch v4 multi-frame normalized profile

`MULTIFRAME-NORMALIZED19` inherits v3's immutable labels and recording split but replaces
`LOWRES12`. Seven 256×144 frames span 8% through 92% of each rally. Long horizontal lines
from the first seven rallies estimate a recording-level foreground-net height, and a
piecewise vertical remap places that divider at `y=0.5`. Upper-frame phase correlation
compensates global translation before temporal-difference weighting. Joint hue/saturation
and value palettes are pooled across all frames in broad overlapping and tight disjoint

The 19 ordered inputs are broad and tight same/swapped assignment costs, swap margins,
orientation-flip evidence, mean swap margin, cross-scale disagreement, minimum/change

alignment response. Exact implementation: [`side_switch_v4.py`](analysis/side_switch_v4.py);
extraction: [`extract-side-switch-v4.py`](scripts/extract-side-switch-v4.py).

### Side-switch v5 player-isolated orientation profile

`PLAYER-ORIENTATION22` inherits v4's seven 256×144 frames and frozen court geometry but

area, aspect, dimensions, and lower-court position; overlapping boxes are suppressed and
at most six player-like proposals remain per frame. Proposal palettes use temporal,
motion, and weak saturation weights, then soft near/far assignment from proposal-foot

The 22 classifier inputs retain six v4 appearance/quality scalars and add same/swapped
player-palette costs, swap/flip evidence, side separation, palette instability, player
appearance change, proposal coverage/count, and near/far support. The first three

### Side-switch CONTINUITY1 verifier

`CONTINUITY1` reuses V5's scalar `playerSwapMargin = sameCost - swapCost` but gives it
a separately constrained role. Within each complete recording, subtract the candidate-
row median and divide by
`max(1.4826 × median absolute deviation, 0.25 × standard deviation, 1e-6)`. Lower
normalized values are stronger evidence that team-to-side assignment remains unchanged.
The verifier can only veto a proposal already selected by the frozen local-peak+soft-
count control; it is not a hard positive gate or a candidate generator.

The final development threshold is `-0.8360349704653693`, chosen with a 90% fit-TP
retention guardrail after LOO evaluation. It has no weight matrix or bias. Exact
implementation: [`side_switch_continuity.py`](analysis/side_switch_continuity.py),
training/evaluation:
[`train-side-switch-continuity-verifier.py`](scripts/train-side-switch-continuity-verifier.py),
and decision:

### Side-switch full-trace candidate union

The full-trace union operates after the existing production heads. It retains all gaps
between consecutive decoded rally ranges, then searches within each range for extremely
strong dead-state peaks. The selected opened-development configuration excludes four
seconds at each range edge, requires `deadState >= 0.98`, applies score-ranked 14-second
NMS per range, and emits a two-second candidate around each peak. It uses the existing
4 Hz probability trace and adds no feature/model inference or video decode.

This is an internal high-recall universe, not an output proposal rail. The follow-up
`FULL-UNION-V5-STATE42` artifact now makes all 704 candidates scoreable. Boundaries use
the frozen whole-rally seven-frame contract. Internal candidates compare fixed
three-second flanks `[t-4,t-1]` and `[t+1,t+4]`, each with seven 256×144 frames. The
generator's four-second edge exclusion keeps both flanks inside the containing range.
All 352 legacy rows reproduce all 42 feature values exactly.

The research ranker consumes either the existing 32-input V5+STATE10 primary view or
that view plus candidate kind and generator score. Its nested-LOO decoder uses no
cadence or re-anchoring. Exact candidate implementation:

### Side-switch v6 detected-player adaptive profile

`DETECTED-ADAPTIVE29` retains six v4 appearance/alignment scalars but replaces v5's
motion components with the pinned OpenCV Zoo MediaPipe person detector. The upstream
block-int8 ONNX is 3,482,053 bytes, Apache-2.0 licensed, and runs through OpenCV DNN on
CPU. Three full-resolution ROI frames are sampled at 15%, 50%, and 85% of every rally.
Each frame is evaluated through four overlapping 62%-coverage ownership tiles. Hip and
shoulder landmarks define torso palettes; geometry and duplicate-hip filters are applied,
then at most two detections per canonical court side remain. Side assignment uses v4's
recording-level net height and a soft canonical hip divider at `y=0.56`. Same-side hip
matches within 0.18 normalized distance provide temporal-consistency weights.

The first three score-zero rallies initialize canonical team palettes. Later rallies are
assigned to the cheaper same/swapped ordering and can update those prototypes at a
maximum exponential rate of 0.12 when player support, confidence, temporal consistency,
side separation, and assignment margin pass the frozen gate. The 29 inputs comprise six
v4 scalars, 20 detected-player identity/localization/quality scalars, and three adaptive
orientation scalars. A separately fitted 26-input ablation holds the first-three-rally
prototypes fixed. Exact implementation:
[`side_switch_player_detector.py`](analysis/side_switch_player_detector.py) and
[`side_switch_v6.py`](analysis/side_switch_v6.py); extraction:
[`extract-side-switch-v6.py`](scripts/extract-side-switch-v6.py). The third-party model,
license, feature rows, both fitted heads, and evaluation are bound by the v6 provenance
artifact.

## Rebuild and parity acceptance

A clean-room production rebuild is acceptable only when all of the following hold:

1. The generated ordered base names exactly equal `BASE_FEATURE_NAMES` and the
   contextual names exactly equal the checked-in production artifact's 520 names.
2. The same source, ROI, analysis window, timestamps, and feature version generate only
   finite rows with stable dimensions.
3. Python reference, browser JavaScript/WASM, and Android agree on checked-in golden
   feature vectors within the tolerance declared by their tests.
4. The golden contextual fixture reproduces the expected unpadded model intervals for
   both production model bundles.
5. Cache keys change when source bytes, ROI, window, decode strategy, resampler/runtime,
   feature configuration, or feature signature changes.
6. Missing-audio and first-frame behavior are explicitly exercised.
7. Production inference parity and known media-decoder differences are recorded in
   [`android/FULL_INFERENCE_PARITY.md`](android/FULL_INFERENCE_PARITY.md).

For `SERVSIDE237-FLIGHT`, browser acceptance additionally requires exact feature-name
order, raw dimensions, tied ranks, frozen near probability, side threshold, review band,
serve-head evidence, and hybrid-gate output. Android serving-side release is blocked
until the same fixture passes natively; see the Android implementation spec.
